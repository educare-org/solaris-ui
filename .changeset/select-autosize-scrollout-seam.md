Select, multi-select and popover follow-ups. The panel keeps the exact fractional trigger width so both seam edges share the same device pixels, and form-field-connected panels render with no shadow on either connected side (a shadow darkens the outer fringe of the panel's side borders and reads as a step against the trigger, most visibly in dark theme). The trigger now tracks its origin with a ResizeObserver while open, so font swaps, container reflows and content-driven growth re-anchor the panel instead of leaving it stale on first open. New `solarisPopoverBordered` input (default `true`): surface/minimal selects pass false so the borderless panel mirrors their borderless trigger, while outline/filled keep the mirrored border. Select and multi-select grow toward the widest option row on first open via the new `autoSize` input (default `true`), capped at the smallest of 480px, the parent width and the viewport, so single-word options stop breaking mid-word while narrow containers keep wrapping; explicit `triggerMinWidth`/`panelMinWidth` or `panelMatchTriggerWidth=false` still win. The floor is measured in an offscreen `max-content` clone (never from the live rows, whose `scrollWidth` would read the floor back and ratchet every open) and applied to the host, so wrapper, trigger and panel grow together within the available room and the size converges instead of growing on every open. Open panels auto-close without restoring focus once the trigger scrolls fully out of view (`solarisPopoverCloseOnTriggerOutOfView`, enabled by both selects), and outside-click closes no longer steal focus or scroll the page back to the trigger (`close({ restoreFocus: false })`).
