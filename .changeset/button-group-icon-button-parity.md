Bring `solaris-icon-button` and `solaris-button-group` to the `solaris-button` size standard. `icon-button` gains `size` (`sm` | `md` | `lg`, default `md`) with the same 3×3 `size` × `density` matrix (outer box via `--solaris-control-height-<density>-<size>` tokens, `sm` → `xs`, `md` → `sm`, `lg` → `md` icon scale); `density` is now `input<T | undefined>` falling back to `ThemeService.density` (previously defaulted to `'compact'`); the host exposes `data-size` + effective `data-density`. Also adds a `chromeless` input (same `size` × `density` footprint with no background/border, glyph enlarged to 60% of the box, hover/active icon micro-interaction with reduced-motion support, `data-chromeless` presence attribute, `solid` icons remapped to the foreground tones so they stay visible without the filled background), `loadingLabel`/`loadingLabelKey` inputs with imperative `aria-label` save/restore parity, and replaces the CSS `::before` loading spinner with the shared `solaris-spinner` component (same indicator as `solaris-button`). `button-group` gains `size` (default `md`, forced onto every `[solaris-button]`/`[solaris-icon-button]` child together with `density` so items never render mixed heights) and exposes `data-size`; `density` also falls back to the theme. Fixes the detached (`attached=false`) gap (the gap token is now consumed via `gap`), and softens the attached dividers with new hex theme tokens (`--solaris-button-group-separator-color` for soft appearances, `--solaris-button-group-separator-on-solid` for `solid` items) instead of the destoando `border-soft`. Attached children render borderless (the group owns the outer ring and dividers, hover/active border colors neutralized) so dividers never double up on mixed appearance or button + icon-button pairs. Both showcase pages are rebuilt on the docs-page-layout pattern with interactive size/density selectors, chromeless/badge demos, and a split-button (button + chevron) preset.
