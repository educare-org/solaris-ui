Refactor `solaris-dialog` to the `solaris-card` / `solaris-selection-card` pattern: panel adapts to content (fixed `size` scale `sm` / `md` / `lg` / `xl` removed in favor of a `fullscreen` flag plus explicit `width` / `height` constraints), 9 placements (`center`, `top`, `bottom`, `left`, `right`, `top-left`, `top-right`, `bottom-left`, `bottom-right`) with 24px offsets, `headerSeparator` / `footerSeparator` opt-out (default `true`), panel `radius` / `density` with theme fallback, fixed `[data-dialog-close]` icon button owned by the container, zero `padding` / `margin` / `gap` defaults with density opt-in, action buttons forwarding `shape` / `density` / `radius` / `icon` / `loading` to `solaris-button`, and `surface` background on `--solaris-surface-base`, with `outline` as the new default appearance (was `surface`). Title and description element ids are now unique per dialog (`<dialog-id>-title` / `<dialog-id>-description`) and wired to the panel via `aria-labelledby` / `aria-describedby` (with `titleKey` / `descriptionKey` / `ariaLabelKey` / action `labelKey` translation support). `autoFocus` now supports `'panel'` and `false` plus per-action `autoFocus`, and `restoreFocus` actually restores focus to the trigger on close. Migration: dialogs relying on the old default paddings should set `density`; the header close button moved to the container.
