Button SSR flash fix and button-group CSS-vars migration. `[solaris-button]` and `[solaris-icon-button]` accept `data-size`, `data-density`, `data-appearance`, `data-color`, `data-shape` and `data-radius` as inputs (attribute wins over the same-named input; the group still wins over both), so server-rendered HTML paints the right variants with CSS alone before hydration. The constructor no longer stamps variant defaults before inputs bind. `SolarisThemeService.density` reads the `data-density-default` attribute on `<html>` (exported as `SOLARIS_DENSITY_DEFAULT_ATTRIBUTE`) before falling back to the `--solaris-density-default` custom property, so SSR and client agree. `solaris-button-group` no longer uses `::ng-deep`: children in attached groups carry `data-group="horizontal|vertical"` (from the group context, which now also exposes `attached` and `orientation`) and opt into attached styling themselves — square middle, flush edge radius via `max()` of both axes, per-appearance divider color, and a subtle `brightness(1.07)` hover lift. `transition: all` narrowed to color, background-color, border-color, box-shadow and filter; `custom` color blocks consume `var()` without fallbacks. Attached buttons use `border-width: 0` so the inset divider spans the full item height.
